## Interpretation

The named sinks are inside `gen_pd_row[*].gen_pd_col[*].u_pd` local logic, with
examples such as:

- `drc_bufs468/A`
- `drc_bufs472/A`
- `g2/B`
- local generated gates under each PD cell

The most likely signal class is a PD detect-enable or clear-derived local
control net. It is not a raw RO phase output, and it is not a phase-buffer
clock-tree output.

## Repair Policy

Allowed in `FINAL_TYPICAL_GENUS_REPAIR_1`:

- permit stronger local inverter/buffer candidates such as `INHDX12`, `BUHDX12`,
  `BUHDX8`, and `BUHDX6`;
- bias high-fanout PD control nets toward local `set_max_fanout 16`;
- bias the same nets toward `set_max_transition 0.45 ns`;
- allow the optimizer to insert a local buffer tree on non-phase control nets.

Not allowed:

- no max-transition relaxation above `500 ps`;
- no broad false paths;
- no phase-clock CTS in Genus;
- no raw RO output overbuffering;
- no change to O13 `BUHDX4 -> BUHDX12` topology.

## Reset/Clear Safety

If `n_6984` is later proven to be reset or asynchronous clear rather than a
local detect-enable signal, buffering is still allowed only with recovery and
removal review. The repair package therefore documents the logical name as
derived from report/netlist evidence, not as a proven RTL semantic name.
