# O6C Fast Tag Encoding Feasibility

Date: 2026-06-02

Branch: `SPADMIC_localtag`

Reviewed HEAD: `1506b050db1f0a86c5c7b912b3364f885fcaff29`

## Problem

The O5b Genus feasibility run removed the old PD timestamp data-freeze path but
did not close timing. The remaining fast-domain blockers include:

- local fast tag self path, around `-1.45 ns`
- local fast tag to PD timestamp path, around `-1.46 ns`
- discrete clock-gating enable checks, around `-1.8 ns`

Solution C investigates whether a shift-only or shift-mostly local tag can
reduce the fast tag self path without changing the production packet.

## Packet Constraint

The production packet is fixed:

```text
HIT W0[7:1] = nfast[6:0]
```

Therefore Solution C cannot export a wider raw tag through the normal packet.
Any production mode must keep the packet-visible fast field at exactly 7 bits.

Forbidden for O6C:

- changing HIT word count
- changing HIT W0 bit positions
- adding production packet words
- replacing `nfast[6:0]` with a raw 64-bit Johnson state
- silently reusing `raw_lfsr_tag` metadata for another encoding

## Required State Count

Current constants:

```text
NFAST_W = 7
FAST_TAG_SEQUENCE_LEN = 127
DLY_MAX_PS = 32000
FAST_HALF_PERIOD_PS = 8 * 50 ps = 400 ps
NFAST_CAPTURE_MAX = 1 + ceil(32000 / 400) = 81
```

A valid compact fast tag should provide more than the expected maximum fast
epochs per conversion. The current 7-bit maximal LFSR has 127 non-zero states,
which is enough for the nominal 32 ns window under the current model.

A 7-bit Johnson counter has only:

```text
2 * 7 = 14 states
```

Fourteen states is not enough for the expected fast epoch range. A direct
7-bit Johnson replacement is therefore rejected.

## Candidate Options

### C1: 7-bit Galois / shift-mostly tag

Status: selected first candidate.

Packet compatibility:

- packet `nfast` width remains 7 bits
- packet bit position remains HIT W0[7:1]
- no new production words
- software decodes with `nfast_encoding = raw_galois_tag`

Proposed sequence:

```text
state_next = {state[5:0], 1'b0}
if state[6]:
  state_next ^= 7'h03
```

The generated software table proves a 127-state sequence from seed `7'h01`.
Known prefix:

```text
1, 2, 4, 8, 16, 32, 64, 3
```

Expected timing effect:

- six bits are pure shift paths
- feedback only fans from the old MSB into two low bits
- no `tag[6] xor tag[5]` Fibonacci cone on every update
- software decode table changes, packet does not

Risks:

- still has XOR/toggle logic on two bits
- tag-to-PD timestamp path remains real
- any offset from changed sequence must be calibrated
- requires RTL experiment before characterization in this mode

### C2: 64-stage fast Johnson with clk_sys decode to 7-bit `nfast`

Status: not first choice.

Pros:

- fast-domain update is shift-only
- one-bit state transition
- no LFSR XOR self path

Cons:

- 64 flops per fast column, 512 fast-domain tag flops total
- captured hit image would need either 64 bits per PD cell or a local decode
- exporting raw Johnson through the normal packet is forbidden
- clk_sys decode before packet may add complexity
- phase tap load and PD matrix wiring increase substantially

This option can be revisited only if C1 characterization/timing evidence is
insufficient and the added internal load is acceptable.

### C3: 64-stage fast Johnson raw debug side channel

Status: debug-only option.

This may be useful for bring-up, but it is not a production packet solution.
The normal packet must still carry a 7-bit decoded or compact encoded `nfast`
field.

## Decode Plan

The O6 software update adds named support for:

```text
legacy_binary_nfast
raw_lfsr_tag
raw_galois_tag
```

Decode tables are generated by:

```text
MPTDC/scripts/analysis/tag_decode.py
tools/mptdc_decode/fast_tag_decode.py
```

Stable table artifacts:

```text
MPTDC/scripts/analysis/tag_decode_tables/raw_lfsr_tag.json
MPTDC/scripts/analysis/tag_decode_tables/raw_galois_tag.json
```

Every characterization manifest must include:

```text
nfast_encoding
fast_tag_encoding
rtl_tag_define_or_parameter
tag_type
tag_decode_mode
tag_width
tag_columns
decode_table_hash
packet_format_version
rtl_head
branch
```

## Characterization Requirement

Before any O6C Genus run:

1. Implement the selected C1 RTL mode explicitly.
2. Run Stage 0 local regression.
3. Run Stage 1 Xcelium smoke with `--char-nfast-encoding raw_galois_tag`.
4. Run Stage 2 medium characterization with streaming analysis.
5. Compare against `O6A_best_current_raw_lfsr_tag`.

Do not run Genus for C1 if packet parsing, tag decode, monotonic reconstruction,
fixed-delay RMS, or calibration smoke regresses unexpectedly.

## O6C RTL Selection

The C1 RTL candidate remains packet-compatible:

```text
MPTDC_FAST_TAG_GALOIS unset:
  mptdc_fast_epoch_tag TAG_ENCODING_SEL = TAG_ENC_LFSR_FIBONACCI
  packet HIT W0[7:1] = raw_lfsr_tag[6:0]

MPTDC_FAST_TAG_GALOIS set:
  mptdc_fast_epoch_tag TAG_ENCODING_SEL = TAG_ENC_GALOIS
  packet HIT W0[7:1] = raw_galois_tag[6:0]
```

No packet words, widths, or HIT/META/EOC bit positions change. The
characterization scripts select the RTL define from `--nfast-encoding`, and the
manifest records the resulting RTL define so software metadata and hardware mode
can be audited together.
