## Delay Diagnosis

The top `FAST_TAG_TO_PD_TS` path is dominated by library sequential cost:

| Component | Delay ps | Notes |
|---|---:|---|
| launch C->Q | 638 | `DFRRQHDX1`, largest single term |
| inserted buffer | 226 | `BUHDX8`, fanout 8 toward one PD column |
| local inverter | 70 | `INHDX2`, inside `mptdc_pd_cell` |
| final local gate | 117 | `ON22HDX1`, timestamp select/freeze cone |
| data path total | 1051 | reported total |
| endpoint setup | 263-264 | `DFRHDX2` timestamp flop |
| uncertainty | 10 | O7 guarded typical uncertainty |

The path is not transition-limited in the timing table: max reported transition
is `204 ps`, below the `500 ps` max-transition rule.  Data path plus setup is
the issue.  Since C->Q plus setup alone is about `901-902 ps`, the reported
path is intrinsically tight at a `900 ps` fast period before any useful
combinational delay is counted.

This makes O8 closure plausible but not guaranteed.  There is enough removable
non-sequential delay (`BUHDX8` plus local gate/inverter, about `413 ps`) for
high-effort mapping/sizing to try, but the C->Q/setup budget leaves little
slack for ordinary synthesized logic.

- O7 reduced WNS to about `-424 ps`, compared with multi-ns failures in older
  pessimistic views.

- Remaining paths are localized and classified.
- The worst family is `FAST_TAG_TO_PD_TS`, which may benefit from high-effort
  sizing/buffering and reduced over-preservation.

- If O8A improves materially, keep architecture stable and continue closure.
- If O8A remains around `-300 ps` or worse, test O8B preserve relaxation and O8C
  raw Galois timing what-if before considering tag-replica architecture.
- Do not run Innovus until typical Genus is near clean.
